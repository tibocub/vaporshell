# Bash compatibility coverage

What vaporshell's default (bash) mode does and does not do compared with bash
itself, measured rather than asserted, and how to keep this current when bash
releases a new version.

> Generated by `tests/coverage/gen-docs.py` from `tests/coverage/templates/`
> and `tests/coverage/probes.txt`. The tables are measurements; edit the
> template or the probes, not this file.

## Reference

- bash-mode reference: `GNU bash, version 5.3.0(1)-release (x86_64-pc-linux-gnu)`
- POSIX-mode reference: `dash 0.5.12-6ubuntu5`
- generated: 2026-09-20 by `tests/coverage/gen-docs.py`


The target is **bash 5.3**. Earlier measurements in `docs/modes.md` were made
against bash 5.2.21; the differences found between the two are recorded in
the release log below.

Probes matching bash in bash mode: **269 of 320**.


## How this is measured

`tests/coverage/probe.py` runs each probe (a few lines of shell, see
`probes.txt`) under the real bash, under dash, and under vaporshell in both
modes, and compares **stdout and exit status**. It does not compare stderr:
error wording is shell-specific.

- **ok**: vaporshell's output and exit status equal bash's.
- **differs**: they do not. For probes marked *bash ...* in the note this is a
  feature vaporshell does not implement yet; nothing here is a known bug
  (known bugs are fixed or listed under *Known deliberate differences*).
- 320+ probes is a sample of behaviour, not a proof of conformance. Areas
  without probes are listed under *Not covered*.

## Keeping up with bash releases

When bash publishes a new release:

1. Build it (`./configure --without-bash-malloc && make`) and note the exact
   version printed by `bash --version`.
2. Re-run the suites against it:
   `BASH_REF=/path/to/new/bash sh tests/check-all.sh build/vaporshell`.
   A failure is either a bash behaviour change or a vaporshell bug; the
   suite name says which mode.
3. Regenerate this document:
   `python3 tests/coverage/gen-docs.py build/vaporshell --bash /path/to/new/bash`
   and `git diff docs/`. Rows that flipped between ok and differs are the
   observable changes.
4. Read the new section of bash's `NEWS` (it is in the source tarball) and add
   a row per relevant item to the release log below. `CHANGES` has the
   bug-fix level detail.
5. Record what was measured and against which build in the release log.

## Known deliberate differences

- **`BASH_VERSION`** is `5.3.0(1)-vaporshell`. Scripts that parse the number
  work; scripts that require the `-release` suffix do not.
- **`RANDOM`** uses its own generator, so seeded sequences differ from bash's
  (the range, `0..32767`, and that seeding is repeatable, are the same).
- **`\u`/`\U` escapes** in `echo -e` and `printf` always produce UTF-8.
  bash's output there depends on the locale.
- **`declare -x`/`-r` listings** (`export`, `readonly` with no arguments) use
  bash's format and sort order.
- **Signals** on the NuttX build are not wired yet (`trap`/`kill` on real
  signals work on host builds only).
- **`ulimit -a`** and **`hash -l`/`-t`** are not implemented; `hash` lists
  entries newest-first where bash's order is its hash order.
- **`kill -l`** and **`set -o`** list only the signals and options vaporshell
  has, not bash's full sets.

## Not covered

No probes exist for: interactive behaviour (line editing, history,
completion, prompts, job control), `PS1`-`PS4` expansion beyond `PS4` under
`set -x`, locale-dependent behaviour, `set -x` trace formatting, `mapfile`,
`coproc`, `shopt` options, and error-message text. "ok" above says nothing
about these.
